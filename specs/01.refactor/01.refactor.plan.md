- 当前: `var startProcessTime = time.Now()`
- 用途: 仅在 `beans/topic_top.go:62` 计算进程运行时间

```go
// beans/init.go
var processStartTime = time.Now()  // 改为私有变量
```

```go
// beans/topic_top.go:62
```

- 满足宪法：状态通过函数显式访问，非全局可修改

### 1.3 Git编译信息变量 → 保持现状+Getter访问

**状态**: 已决策

**位置**: `consts.go:23-27`

**分析**:
- 这5个变量由编译时 `-ldflags -X` 注入
- 本质上是"构建配置"，不是运行时状态
- 仅在 `console.go:98-102` 日志输出中使用

**决策**: 保持变量，添加Getter函数返回只读副本

**代码变更**:

```go
// consts.go
// 变量保持原样（由编译时注入）
var GitBranchName string
var GitCommitId string
// ... 其他3个

// 新增：返回只读副本
type BuildInfo struct {
    BranchName    string
    CommitId      string
    CommitMessage string
    CommitTime    string
    AppBuildTime  string
}

func GetBuildInfo() BuildInfo {
    return BuildInfo{
        BranchName:    GitBranchName,
        CommitId:      GitCommitId,
        CommitMessage: GitCommitMessage,
        CommitTime:    GitCommitTime,
        AppBuildTime:  AppBuildTime,
    }
}
```

**理由**:
- 构建配置非运行时状态，不违反宪法精神
- Getter返回值而非指针，天然只读
- 集中访问点，便于后续替换

### 1.4 subUnsubNames等 → 封装为配置对象

**状态**: 已决策

**位置**: `consts.go:30-32`

**分析**:
- 3个切片定义内置命令的名称、示例、说明
- 实际是常量配置，不应为var
- Go不支持const切片

**决策**: 封装为不可变配置对象

**代码变更**:

```go
// consts.go
// 删除原有var定义

// 内置命令配置
type builtinCommand struct {
    Name    string
    Example string
    Note    string
}

var builtinSubCommands = []builtinCommand{
    {Name: "sub", Example: "sub top", Note: "订阅主题"},
    {Name: "unsub", Example: "unsub top", Note: "取消订阅主题"},
}

// 如需暴露，添加Getter返回只读副本
func GetBuiltinSubCommands() []builtinCommand {
    // 返回副本防止外部修改
    result := make([]builtinCommand, len(builtinSubCommands))
    copy(result, builtinSubCommands)
    return result
}
```

**理由**:
- 结构体比平行切片更安全（字段一一对应）
- Getter返回副本，防止外部修改
- 明确表达"这是配置数据"的语义

## P2: 错误处理修复方案

### 2.1 错误处理原则

**决策**：
1. **显式忽略原则**：若错误可以安全忽略，必须使用 `_ =` 显式忽略 + 注释说明原因
2. **分层处理**：
   - 边界层（网络IO）：记录日志 + 关闭连接 + 清理资源
   - 业务层（文件操作）：返回错误，让调用方决定
   - 初始化层（正则编译）：失败即panic（不可恢复）

### 2.2 具体修复点

#### 2.2.1 road/app.go 心跳写入失败

**决策**：采用显式忽略 + 注释

```go
// 修改后
if _, err := conn.Write(heartbeatBuffer); err != nil {
    logo.Info("heartbeat write failed, addr=%s, err=%v", conn.RemoteAddr(), err)
    _ = conn.Close() // 显式忽略：commonLink.Close()永不为error，仅设置isClosed标志
    continue
}
```

#### 2.2.2 tools/file.go ReadTailLines

**决策**：改为返回 error，破坏性变更


## P3: 表格驱动测试重构

### 3.1 规范定义

#### 规范1: 测试用例结构

```go
func TestXxx(t *testing.T) {
    type args struct {
        // 输入参数字段
    }

    tests := []struct {
        name    string        // 测试场景描述
        args    args          // 输入参数
        want    Type          // 期望返回值（可选）
        wantErr bool          // 是否期望错误
        check   func(t *testing.T, got Type) // 可选：自定义验证
    }{
        {name: "正常路径", ...},
        {name: "空值输入", ...},
        {name: "边界条件", ...},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := Xxx(tt.args...)
            if (err != nil) != tt.wantErr {
                t.Errorf("Xxx() error = %v, wantErr %v", err, tt.wantErr)
                return
            }
            if tt.check != nil {
                tt.check(t, got)
            } else if got != tt.want {
                t.Errorf("Xxx() = %v, want %v", got, tt.want)
            }
        })
    }
}
```

#### 规范2: 边界条件覆盖要求

每个被测函数至少覆盖：
- 正常路径
- 空值/零值输入
- 无效输入（空字符串、负数、nil等）
- 边界值（最小/最大值）

#### 规范3: 外部依赖处理

**文件系统依赖**：使用 `os.CreateTemp` 创建临时文件，确保测试可重复
```go
func TestReadFileTailLines(t *testing.T) {
    tmpfile, err := os.CreateTemp("", "test*.log")
    if err != nil {
        t.Fatal(err)
    }
    defer os.Remove(tmpfile.Name())
    // 写入测试数据，执行测试...
}
```

**状态**: 已决策

**决策**: 采用方案A（三大组件），Console保留为Facade，保持向后兼容

### 4.2 目标架构

```
┌─────────────────────────────────────────────┐
│              Console (Facade)               │
```

### 4.5 实施步骤

1. **创建CommandManager**：提取commands相关逻辑
2. **创建TopicManager**：提取topics相关逻辑

4. **验证兼容性**：确保现有调用方无需修改

### 4.6 注意事项

- **零破坏性**：所有公共方法签名保持不变
- **逐步迁移**：可先实现CommandManager，再实现TopicManager
- **测试先行**：为Manager组件编写单元测试，再重构Console
