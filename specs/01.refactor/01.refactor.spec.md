# 项目架构重构规范

本文档记录项目当前违反《项目开发宪法》的问题及修复方案。

---

## 问题清单

### P1: 存在多个包级全局变量（违反宪法第3.2条）

**严重程度**: 🔴 高 - 违反"不可协商"条款

**问题描述**:
宪法第3.2条明确规定："绝不允许使用全局变量来传递状态，所有依赖必须通过函数参数或结构体成员显式注入"。

当前代码中存在以下全局变量：

| 位置 | 变量 | 用途 | 影响 |
|------|------|------|------|
| `beans/init.go:15` | `startProcessTime` | 记录进程启动时间 | 无法测试，隐式状态 |
| `consts.go:23-27` | `GitBranchName`等5个变量 | Git编译信息 | 全局可修改，不安全 |
| `consts.go:30-32` | `subUnsubNames`等3个切片 | 内置命令定义 | 运行时可能被修改 |
| `road/session_impl.go:25-26` | `globalIdGenerator` | Session ID生成器 | 并发测试困难 |
| `road/session.receive.go:23` | `typeOfBytes` | 反射类型缓存 | 实际上无需全局 |

**风险分析**:
1. **测试困难**: 全局状态导致测试间互相影响，无法并行执行
2. **隐式耦合**: 代码间通过全局变量隐式依赖，难以追踪数据流
3. **并发问题**: 全局变量需要额外的同步机制，容易出错
4. **无法替换**: 不符合宪法"方便日后有更优的solution后无脑替换"的要求

---

### P2: 多处错误被静默忽略（违反宪法第3.1条）

**严重程度**: 🔴 高 - 违反"不可协商"条款

**问题描述**:
宪法第3.1条规定："不可协商：所有错误或异常都必须被显式处理"。

当前代码中存在以下错误被忽略的情况：

| 位置 | 代码 | 问题 | 后果 |
|------|------|------|------|
| `road/app.go:77-78` | `conn.Write(); err1 != nil { continue }` | 写入错误仅跳过，无日志 | 网络问题无法定位 |
| `road/app.go:97-99` | `session.Handshake(); err != nil { return }` | 握手错误直接返回 | 连接失败原因不明 |
| `tools/file.go:25-27` | `os.Open(); err != nil { return nil }` | 错误信息丢失 | 调用方无法区分原因 |
| `beans/command_deadlock_detect.go:39-40` | `regexp.Compile(); _` | 正则编译错误被忽略 | 可能导致panic |
| `topic.go:35` | `logo.Error()` 仅打印，未返回 | 启动失败不阻止 | 无效Topic静默运行 |

**风险分析**:
1. **故障排查困难**: 生产环境出现问题时无日志可追踪
2. **数据丢失**: 错误被忽略可能导致数据未正确处理但调用方不知情
3. **程序不稳定**: 未检查的错误可能引发后续连锁反应（如panic）

---

### P3: 测试文件未采用表格驱动测试（违反宪法第2.2条）

**严重程度**: 🟡 中 - 违反测试铁律

**问题描述**:
宪法第2.2条规定："单元测试必须优先采用表格驱动测试（Table-Driven Tests）的风格"。

当前测试文件问题：

| 文件 | 问题函数 | 问题描述 |
|------|----------|----------|
| `tools_test.go` | `TestNilToHtmlTable` | 单一样例，无边界测试 |
| `road/session_test.go` | `TestMakeFunc` | 单一场景，未覆盖异常情况 |
| `jwtx/jwt_test.go` | `TestSign`, `TestExpiration` | 独立函数，重复代码多 |
| `tools/file_test.go` | `TestReadFileTail` | 依赖外部文件，不可重复 |
| `tools/file_test.go` | `TestTimeSort` | 非表格驱动，场景单一 |
| `tools/html_test.go` | (假设存在) | 需要检查是否表格驱动 |

**风险分析**:
1. **测试覆盖不足**: 单一样例难以覆盖边界条件
2. **可维护性差**: 新增测试需要复制粘贴，容易出错
3. **可读性低**: 分散的测试逻辑难以理解被测函数的完整行为

---

### P4: Console结构体职责过多（违反宪法第1.4条）

**严重程度**: 🟡 中 - 违反单一职责原则

**问题描述**:
宪法第1.4条规定："任何file, class, struct, method等代码实体都必须为单一目标设计"。

`Console` 结构体（`console.go:30-38`）同时负责：
- Web服务生命周期管理（`app`）
- HTTP路由注册（`registerHandlers`）
- 命令注册与管理（`commands`）
- Topic管理（`topics`）
- 认证状态跟踪（`lastAuthTime`）
- pprof端点注册（`enablePProf`）
- 内置命令注册（`registerBuiltinCommands`）

**代码复杂度**:
- `console.go`: 270行
- 涉及至少7个不同的职责领域

**风险分析**:
1. **修改影响面广**: 修改一个功能可能意外影响其他功能
2. **测试困难**: 需要模拟所有依赖才能测试单个功能
3. **无法局部替换**: 无法单独替换命令系统或Topic系统

---

### P5: 过度抽象与复杂反射体系（违反宪法第1.3条）

**严重程度**: 🟡 中 - 违反简单性原则

**问题描述**:
宪法第1.3条规定："简单的函数和数据结构优于复杂的接口和继承体系"。

`road/component/` 包存在过度设计：

| 组件 | 问题 | 复杂度 |
|------|------|--------|
| `Service` | 使用`reflect.Type`和`reflect.Value`保存组件 | 运行时反射 |
| `Handler` | 包含`RespondMethodType`反射字段 | 动态方法创建 |
| `ExtractHandler` | 100+行反射逻辑筛选方法 | 难以调试 |
| `session.receive.go:184` | `reflect.MakeFunc`动态创建回调 | 性能开销 |

**风险分析**:
1. **性能损失**: 反射带来运行时开销
2. **类型不安全**: 编译期无法检查类型错误
3. **可读性差**: 反射代码难以理解和维护
4. **调试困难**: 反射相关的panic堆栈信息难以理解
